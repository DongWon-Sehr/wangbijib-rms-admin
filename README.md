# 왕비집 예약관리 시스템 어드민 (wangbijib-rms-admin)

Google Workspace 플랫폼을 활용하여 왕비집 전 지점의 예약을 효율적으로 모니터링하고, 예약금 상태 및 예약 슬롯을 최적화하여 매출 관리를 돕는 백오피스 관리자 웹 애플리케이션입니다.

현재 앱 버전: **v2.2.20**.

v2.2.20: 예약·설정·로그 전체의 60초 동기화, 설정·로그 Optimistic UI, 시스템 로그의 클라이언트 필터·변경 전후 표와 공통 로딩 스피너를 적용했습니다.

---

## 🛠️ 기술 스택 (Technology Stack)

- **Frontend:** Vue.js 3 (Composition API, CDN), Tailwind CSS (CDN), Phosphor Icons
- **Backend:** Google Apps Script (GAS)
- **Database:** Google Sheets
- **Libraries:** Summernote Lite (WYSIWYG 메일 템플릿 에디터), Kakao JS SDK (알림톡 연동)
- **Integration:** Google Calendar API, Gmail API

---

## 🌟 핵심 기능 (Key Features)

1. **예약 통합 리스트:**
   - 지점, 상태(대기/확정/취소), 예약금 여부에 대한 다중 복합 필터 및 정렬 기능.
   - 모바일 환경 최적화를 위한 터치 기반 **당겨서 새로고침(Pull-to-Refresh)** 및 인라인 예약 상태/예약금 상태 즉시 변경.
2. **실시간 동적 알림 (GNB Bell UI):**
   - 별도 DB 구축 없이 프론트엔드가 실시간 계산하여 알려주는 미결 상태 알림. 동일 예약 건에 대한 알림은 하나로 통합되고 다중 뱃지 형태로 노출됩니다.
    - **`[👥 중복 의심]`** (노란 뱃지, v2.1.0): 동일 이메일/고객명/연락처 기반 미래 예약 중복 감지 및 수동 묶음 그룹 알림.
    - **`[⚠️ 이메일 오류]`** (빨간 뱃지, v2.1.0): 이메일 정규식 형식 오류, 도메인 오타(gmial.com 등) 및 발송 실패(Mailer-Daemon 반송) 자동 감지.
    - **Optimistic UI 즉시 반영 (v2.1.1)**: 주소 변경 재발송, 스레드 초기화, 또는 예약 저장 완료 시 메모리 내 반송 상태를 즉시 해제하여 모달 닫힘 즉시 필터 뱃지 카운트 실시간 차감.
    - **`[임박]`** (빨간 뱃지, 1분마다 자동 갱신): 예약 대기 상태(`pending`)인 예약건 중 현재 시각 기준 **6시간 이내** 방문이 임박한 예약.
    - **`[예약대기]`** (노란 뱃지): 미래 방문건 중 확정 대기 중인 예약.
    - **`[예약금대기]`** (주황 뱃지): 미래 방문건 중 예약금 입금 대기 중인 예약.
    - **`[환불필요]`** (파란 뱃지): 방문 예정 시각이 지났으나 예약금이 완료(확정) 상태인 예약.
    - 알림 카드 클릭 시 해당 예약 상세 모달 또는 중복 비교 모달을 즉시 팝업하여 편리한 후속 액션 연동.
3. **중복 예약 비교 & 관리 & 확인 메일 발송 (v2.1.0 ~ v2.1.4):**
   - 2건 이상의 중복 예약을 가로 테이블로 한눈에 비교하는 전용 모달.
   - 단건 예약 제외, 단건 예약 취소, 중복 아님 처리, 관리자 수동 묶기/해제 지원.
   - 중복 예약 리스트 그룹 접기/펼치기 아코디언 및 상단 일괄 토글 기능.
   - **스레드 기반 중복확인 메일 발송 (`ModalDuplicateMailSelect`)**: Gmail 스레드가 연동된 예약 건만 선택 가능하며(`메일발송 가능` 뱃지), 정형화된 영문 안내 메일 발송 및 `mail_sent_at` 자동 기록.
   - **메일 템플릿 & 레이아웃 최적화 (v2.1.1 ~ v2.1.3)**: 4바이트 이모지 인코딩 보장(`_encodeEmojisToEntities`), 좌측 정렬(`max-width: 680px`), 왕비집 서포트팀 표준 브랜드 테이블 푸터 본문 일체화(지메일 접힘 방지).
   - **발송 중 로딩 스피너 및 발송시간 즉시 반영 (v2.1.2 ~ v2.1.3)**: 백엔드 RPC Date 직렬화 안전성 보장, 발송 중 그룹 헤더 `[ 🔄 발송 처리 중... ]` 표시 및 완료 즉시 발송시간 낙관적 반영(0초 전환).
   - **단일 중복 제외 & 전체 중복아님 최적화 (v2.1.4)**: `excludeReservationFromGroup` 시트 삭제 및 고아 해제, RPC `earliestDate` Date 직렬화 버그 수정, 데스크톱/모바일 버튼 문구 완전 통일(`[확인메일 발송]`, `[전체 중복아님]`, `[수동 묶음 해제]`, `[이 건 제외]`).
   - **신규 스레드 Gmail 라벨 상태 동기화 (v2.1.1)**: 주소 변경 재발송 및 신규 스레드 생성 시 예약 상태(확정/취소/대기/예약금)를 감지하여 지메일 라벨 정확히 동기화.
   - **다중 레이어 모달 ESC 계층 닫힘 제어**: Alert/Confirm 팝업 $\rightarrow$ 중복확인 모달 $\rightarrow$ 드롭다운 $\rightarrow$ 기본 상세 모달 순으로 닫히도록 완벽 격리.
   - 전용 DB 시트(`duplicate_group`) 및 `MigrationService`를 통한 스키마 자동 동기화, 10분 주기 정기 배치(`ReservationBatch.run10MinuteBatch`).
4. **지점별 슬롯 마스터/오버라이드 관리:**
   - 특정 지점의 날짜별 슬롯을 일괄 제어(Batch API) 및 개별 재정의(ON/OFF) 기능.
   - 대량의 이벤트가 캘린더에 동기화되는 속도 향상을 위해 **Google Calendar Batch API** 및 백그라운드 지연 처리 큐 아키텍처 탑재.
5. **WYSIWYG 메일 템플릿 에디터 & 메일 연동:**
   - Summernote를 활용해 HTML 메일을 편집하고 예약 데이터 치환자(`[[customer_name]]` 등)를 적용하여 고객에게 안내 메일 발송.
   - 외부 위젯 연동 오류로 메일 스레드가 누락된 경우, 관리자가 즉시 **신규 메일 스레드를 강제 생성**하여 예약 확정 내역을 고객에게 전달하고 향후 원활한 템플릿 발송을 지원.
   - **Gmail 스레드 ID 자동 보정 (v2.2.1)**: 자유 입력 노트는 Gmail 검색어에서 제외하고, 검색 결과를 예약 요청 시각으로 좁힌 뒤 후보가 여러 개일 때만 메일 본문의 노트와 비교합니다. 검색 단계별 건수와 ID를 찾지 못한 예약을 로그에 남깁니다.
6. **구글 캘린더 및 Gmail 라벨 연동:**
   - 예약 확정/취소 시 캘린더 이벤트 자동 등록/삭제 및 Gmail 스레드에 관련 지점 및 예약 진행 단계 라벨 실시간 자동 동기화.
7. **조회 API 오류 재시도 (v2.2.0):**
   - Apps Script가 저장소 읽기 중 `INTERNAL` 오류를 반환하면 데이터 조회 API만 최대 2회 재시도합니다(총 3회 호출, 재시도 전 0.4초·0.8초 대기).
   - 예약 저장·상태 변경·메일 발송 등 데이터 변경 API는 중복 실행을 막기 위해 재시도하지 않습니다. 재시도가 모두 실패하면 기존 오류 처리로 넘어갑니다.
8. **Google 로그인과 권한 관리 (v2.2.6, 세션 보존 v2.2.19):**
   - Google OAuth 로그인 후 `/exec`로 돌아오는 인증 코드를 서버에서 교환합니다. 인증된 이메일이 활성화된 `user` 시트 계정과 일치해야 입장할 수 있습니다.
   - 로그인 화면의 버튼 문구는 `Google 계정으로 로그인`으로 고정하고, 로그인 URL 준비 전에는 버튼을 비활성화합니다. 사용자 등록 안내는 관리자 문의 문구로 표시합니다.
   - 브라우저 `localStorage`에 무작위 세션 토큰을 저장합니다. 저장된 토큰이 유지되고 서버의 7일 만료 전이면 재접속 시 로그인 상태를 복원합니다. 앱 코드가 저장된 세션 토큰을 삭제하는 시점은 사용자가 명시적으로 로그아웃했을 때뿐입니다. 초기 세션 확인 실패·통신 오류·OAuth 응답 오류에는 기존 토큰을 보존하며, 사용자 정보 저장 후 세션 확인이 실패해도 자동 로그아웃하지 않습니다. 인증에 실패하면 보호된 화면과 API 접근은 차단합니다.
   - 명시적 로그아웃은 서버 세션을 폐기하고 앱 전용 로컬·세션 저장값과 화면 데이터를 지웁니다. 앱 전용 Cache Storage가 있으면 함께 정리합니다. 일반 브라우저 HTTP 캐시와 Google 계정 쿠키는 웹앱에서 지울 수 없습니다.
   - 각 API 요청마다 현재 계정 상태와 역할·지점 권한을 다시 확인합니다. 관리자만 사용자 정보를 변경할 수 있고, 매니저의 예약 조회와 지점 필터에는 허용된 지점만 표시됩니다. 허용 지점이 없으면 필터에 안내 문구가 나타납니다.
   - 사용자 정보 저장 중에는 설정 모달의 스피너만 표시하고, 저장·목록 갱신이 끝난 뒤 완료 알림을 띄웁니다.
   - 웹앱 진입 시 사용자 목록과 `user_branch_permission` 시트의 활성 지점 권한을 함께 읽어, 사용자 수정 화면의 체크박스 선택 상태로 표시합니다.
9. **시스템 로그 (v2.2.7, 조회·변경 내역 개선 v2.2.20):**
   - 관리자 전용 네 번째 메뉴에서 데이터 변경·메일 발송 작업을 초 단위 시각, 담당자, 작업, 대상 ID, 대상, 내용, 결과로 확인합니다. 초기 로드·60초 자동 동기화·데이터 새로고침에서 전체 로그를 가져오고, 기본 최근 7일의 날짜 범위·검색·결과·`target_type` 필터와 정렬은 클라이언트 메모리에서 처리합니다. 필터 변경이나 스크롤은 서버를 호출하지 않습니다. 예약 대상에는 `이름 (이메일)` 형식으로 저장·표시하며, 이메일이 없으면 이름만 표시합니다. 중복 확인 메일의 대상 ID는 메일을 보낸 예약 ID입니다. 예약 정보 수정은 실제 변경 필드의 변경 전·후 값을 `구분 / 변경 전 / 변경 후` 표로 표시하며, 변경 전 값이 없으면 해당 셀은 빈칸으로 표시합니다. JSON의 지점 ID는 보존하며 표에서는 지점명으로 표시합니다. 대상의 지점·사용자·메일 템플릿·중복 그룹·메일 대화는 이름으로, 슬롯 ID는 시간으로 표시하고 ID는 대상 ID 열에만 노출합니다. 연결 데이터가 없으면 `지점 정보 없음` 등으로 표시하며 기존 로그에 저장된 이름은 보존합니다. 표시된 이름도 메모리 검색에 포함합니다. 슬롯 변경은 지점을 대상으로 기록하고, 단건 변경의 슬롯 ID와 시간은 내용에 표시합니다.
   - 작업 내역은 인증된 계정으로 서버에서 기록합니다. API 이름이나 요청 JSON 전체를 화면과 기록 시트에 저장하지 않습니다. 로그인·조회 호출은 기록하지 않습니다.
   - 예약 발송 시각을 갱신하는 외부 `doPost` 요청도 기록하며 담당자는 `SYSTEM`으로 표시합니다. 1분 주기 예약 처리와 날짜별 슬롯 동기화 트리거는 웹앱 사용자 작업이 아닙니다.
   - 변경·발송 요청 직후 메모리에 `처리 중` 로그를 추가하고 서버 응답의 실제 로그로 교체합니다. 서버 실패 시 임시 로그를 제거하고 서버가 반환한 실패 로그를 표시합니다. 네트워크 오류로 응답이 없으면 임시 로그를 제거하고 다음 동기화에서 실제 기록을 확인합니다. 수동 알림톡 완료도 별도 재조회 없이 응답 로그를 반영합니다.
   - 로그 탭의 최초 데이터는 앱 초기 로드에서 가져옵니다. 데스크톱·모바일 모두 탭 재진입은 메모리 데이터를 표시하며 서버를 호출하지 않습니다. 로그 전용 새로고침 버튼은 없고, GNB의 전체 새로고침 버튼 또는 60초 동기화로 예약·설정·로그를 함께 갱신합니다. 초기 로딩은 공통 스피너, 전체 새로고침·자동 동기화는 GNB 회전 아이콘으로 표시합니다.
   - 예약금 금액과 상태를 함께 변경하면 두 항목 모두 변경 전·후 표에 기록합니다. 요청 JSON 순서와 관계없이 저장되는 로그 JSON의 변경 항목 순서를 고정하며, `예약금 상태` 바로 다음에 `예약금`을 저장합니다. UI는 저장된 순서대로 표시합니다. 리스트에서 예약금 상태만 변경하는 경우도 변경 전·후 값을 표로 기록합니다.
   - `activity_log`는 기존 `MigrationService.setup()`의 전체 스키마 점검에 포함됩니다. Apps Script 에디터의 **`runSchemaMigration`** 또는 관리자 **설정 → 시트 구조 점검**에서 누락된 시트·컬럼을 추가할 수 있습니다. 기존 시트의 대상 컬럼은 `target_type`, `target_id`, `target`, `details`, `status` 순서로 정렬되며, 시트가 아직 없을 때는 첫 작업 기록 시 자동 생성됩니다.

10. **전체 데이터 동기화와 Optimistic UI (v2.2.20):**
    - 60초마다 예약·지점·슬롯 마스터·기본/커스텀 슬롯·메일 템플릿·중복 그룹·반송 데이터를 병렬 조회합니다. 관리자는 사용자·시스템 로그도 포함합니다. Vue 메모리 상태를 갱신하여 목록·설정·로그와 관련 필터·카운트도 다시 계산합니다.

## 🚀 배포 가이드 (Deployment via clasp)

본 프로젝트는 Google Apps Script로 작성되었으며, `clasp` 도구를 사용하여 배포합니다.

### 1. clasp 설치 및 로그인
```bash
# 글로벌 clasp 설치
npm install -g @google/clasp

# Google 계정 권한 인증 (웹 브라우저를 통한 인증 완료 필요)
clasp login
```

### 2. Code Push (업로드)
프로젝트 루트 폴더에는 `.clasp.json` 설정 파일이 존재합니다.
```bash
# 로컬 수정 코드를 Google Apps Script 프로젝트의 Head에 업로드
clasp push

# 업로드 상태 유지하며 실시간 변경사항 감지 후 업로드
clasp push --watch
```

### Google 로그인 설정

이 브랜치의 로그인은 Google OAuth 웹 애플리케이션의 authorization code를 서버에서 교환합니다. `Config.GOOGLE_CLIENT_ID`와 **같은 OAuth 클라이언트**의 client secret을 Apps Script 프로젝트의 **Script Properties**에 `GOOGLE_OAUTH_CLIENT_SECRET` 이름으로 저장해야 합니다. 기존 secret이 노출되지 않았고 확인 가능하다면 재사용할 수 있습니다. 노출되었거나 확인할 수 없을 때만 새 secret을 발급하세요. secret을 소스 코드나 브라우저 코드에 넣지 마세요.

GCP의 Authorized redirect URIs에는 운영 배포의 정확한 `https://script.google.com/macros/s/.../exec` 주소를 등록합니다. 별도 테스트 배포를 쓰면 그 `/exec` 주소도 등록해야 합니다. 웹 앱은 **Execute as: Me**, **접근 권한: Anyone (`ANYONE_ANONYMOUS`)**로 배포하고, 앱의 보호된 API는 Google 로그인으로 발급한 세션을 검증합니다. 로그인 식별에 `UserProperties`나 브라우저의 이메일 값을 사용하지 않습니다.

로그인 후 브라우저 `localStorage`에는 무작위 세션 토큰을 저장합니다. 서버는 SHA-256으로 해시한 토큰 키와 만료 시각을 Script Properties에 저장하고, 6시간 CacheService는 조회 속도 향상에만 사용합니다. 브라우저에 토큰이 남아 있고 발급 후 7일이 지나지 않았으면 재접속하거나 서버 캐시가 비워져도 세션을 복원합니다. 만료된 토큰과 비활성 사용자는 서버에서 접근을 거부하며, 브라우저 토큰은 그대로 보존합니다. 새 Google 로그인이 성공하면 검증된 새 토큰으로 교체합니다.

앱 코드의 브라우저 저장값 정리는 명시적 로그아웃에서만 실행합니다. OAuth 검증용 일회성 `state`는 응답 처리 후 소비합니다. 초기 세션 확인이나 사용자 정보 저장 후 세션 확인이 실패해도 자동 로그아웃 또는 저장된 토큰 삭제를 실행하지 않습니다. 브라우저 자체의 사이트 데이터 삭제·저장소 정책까지 제어하는 기능은 아니므로 모바일 홈 화면 앱의 재접속도 실제 기기에서 확인해야 합니다. 사용자 비활성화 또는 권한 변경은 다음 요청부터 적용됩니다. 공용 기기에서는 사용 후 앱에서 로그아웃하세요.

배포 전에 `node --test tests/*.test.cjs`를 실행하세요. 60초 전체 동기화, 설정·로그의 응답 전 즉시 반영 및 실패 롤백, 생성 ID 교체, 늦은 동기화 응답 폐기도 테스트합니다. 인증 테스트는 초기 인증 실패 시 토큰 보존, 잘못된 OAuth 응답 처리, 사용자 정보 저장 후 인증 실패 시 자동 로그아웃 방지, 명시적 로그아웃 시 저장값 정리를 포함합니다. 배포 후 등록 계정 로그인, 브라우저와 모바일 홈 화면 앱 재접속 시 세션 복원, 로그아웃, 미등록 계정 접근 거부와 관리자 시스템 로그 표시를 `/exec`에서 확인합니다.
