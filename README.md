# 왕비집 예약관리 시스템 어드민 (wangbijib-rms-admin)

Google Workspace 플랫폼을 활용하여 왕비집 전 지점의 예약을 효율적으로 모니터링하고, 예약금 상태 및 예약 슬롯을 최적화하여 매출 관리를 돕는 백오피스 관리자 웹 애플리케이션입니다.

현재 앱 버전: **v2.3.3**.

v2.3.3 변경 내역 (2026-10-19):

- 예약 상세 모달의 메일 발송·메일 초기화·예약 이메일 변경은 요청 후에도 모달을 유지합니다. v2.3.0에서 요청 없이 추가됐던 모달 즉시 닫기를 되돌렸습니다.
- Elfsight 위젯: `Wangbijib Myeongdong Central Branch`와 `Hansik Wangbijib Central Branch`의 지점명과 설명 사이에 `🧀 Get Free Grilled Cheese with Reservation` 안내 줄을 표시합니다. 신규 지점 `Hansik Wangbijib Central Branch`를 최대 인원 46으로 등록하고, 명동 센터점 설정 키를 변경된 지점명 `Wangbijib Myeongdong Central Branch`로 맞췄습니다. 전체 소개 문구와 지점 카드 설명의 더보기(`Read more`/`more`)를 데스크톱·모바일 모두 첫 진입 시 모두 펼칩니다.
- 기본 슬롯이 설정되지 않은 지점·시간대의 수용 인원은 `SlotService.DEFAULT_SLOT_CAPACITY`(3)로 처리합니다. 기본 슬롯 행이 있으면 0이나 비활성도 그대로 마감으로 봅니다. 신규 지점이 기본 슬롯 설정 전에 캘린더가 전부 막히던 문제를 해결합니다.

v2.3.2 변경 내역 (2026-10-15):

- 이슈 필터(중복 의심·이메일 오류)는 상단 날짜 구간 필터를 무시하고 방문일 기준으로 동작합니다. 중복 그룹은 멤버 전원의 방문일이 지났으면 목록과 카운트에서 제외하고, 한 건이라도 오늘 이후면 그룹 전체를 표시합니다.
- 이슈 필터 활성 시 `지난 건 포함` 토글을 제공합니다. 켜면 방문일이 지난 중복 그룹·이메일 오류 건도 표시하며, 뱃지 카운트는 토글과 무관하게 오늘 이후 기준을 유지합니다. 이슈 필터를 해제하면 토글은 꺼집니다.
- 모바일 중복 그룹 헤더의 감지 사유·발송 상태와 액션 버튼을 별도 줄로 분리하고 버튼 문구가 줄바꿈되지 않도록 했습니다.
- 지점 필터를 드롭다운 멀티셀렉트(`지점 선택 (N/M)`)로 바꿨습니다. 앱 진입 시 접근 가능한 전 지점이 선택되며 `전체 선택 해제`를 누르면 목록이 비어 있게 됩니다. 전체 선택 여부에 따라 `전체 선택`/`전체 선택 해제` 버튼 하나만 표시됩니다.
- PC 필터 바를 검색·날짜·상태·예약금·지점·이슈 순서의 한 줄로 정리하고(부족하면 항목 단위 줄바꿈), 모바일 아코디언도 같은 순서로 맞추고 정렬을 맨 아래로 내렸습니다. 페이징 푸터 크기를 줄였습니다.
- 데스크톱 예약 테이블에 `비공개 메모` 열을 추가하고, 날짜·지점·상태 등 고정 성격의 열은 내용 폭에 맞게 줄이며 고객명·이메일·메모 열은 말줄임 처리하며 이메일 옆에 복사 버튼을 두었습니다. 관리자 메모는 더 이상 빨간색으로 표시하지 않습니다.

v2.3.1 변경 내역 (2026-10-14):

- 시스템 로그에 작업자의 공인 IP(`ip` 컬럼)를 기록하고 담당자 옆 `IP` 열에 표시하며 검색에 포함합니다. 브라우저가 `api.ipify.org`에서 조회한 값을 세션 토큰과 함께 `{token, ip}` 봉투로 전달하고, 앱 진입·60초 동기화·네트워크 복구 시 갱신합니다. 조회 실패는 오류 표시 없이 빈 값으로 기록합니다.
- `activity_log` 컬럼 정의를 `MigrationService.SCHEMA` 한 곳으로 통합하고, 기록 시 시트 생성·컬럼 정렬을 하던 로직을 제거해 다른 시트와 같이 `runSchemaMigration`으로만 구조를 관리합니다. 배포 후 마이그레이션을 먼저 실행해야 `ip` 컬럼이 추가되고 로그가 기록됩니다.
- `WebApiTest.js`의 중복 정의된 테스트 함수 2개를 제거했습니다.

v2.3.0 변경 내역 (2026-10-14):

- 예약·설정·로그의 Optimistic UI와 실패 시 롤백을 보완했습니다. 설정 저장은 모달을 즉시 닫고 처리 결과를 백그라운드에서 반영합니다. 메일 요청은 예약 모달을 유지한 채 백그라운드로 처리합니다.
- 최초 로드·60초 동기화·GNB 새로고침에 전체 데이터를 포함하며, 시스템 로그 탭 재진입·검색·필터는 메모리에서 처리합니다. 최초 로딩은 공통 스피너를 사용합니다.
- 사용자 액션의 로그 명칭·분류·대상 ID를 정리하고, 실제 저장값의 변경 전·후를 JSON으로 기록해 표로 표시합니다. 자동 후속 처리 로그와 수동 묶음 해제 유형은 제거했습니다.
- 지점 추가를 지원하고, 설정의 시트 구조 점검 버튼과 별도의 수동 묶음 해제 기능을 제거했습니다.
- Elfsight 위젯의 모바일 지점 설명 줄바꿈·강조를 복구하고, Central Branch의 `✨ Newly Opened` 배지와 이모지 시인성을 개선했습니다. 위젯 코드는 Elfsight에 별도로 적용합니다.

버전은 명시적인 변경 요청이 있을 때만 올리고, 코드 수정 시 관련 문서를 함께 갱신합니다.

## 🛠️ 기술 스택 (Technology Stack)

- **Frontend:** Vue.js 3 (Composition API, CDN), Tailwind CSS (CDN), Phosphor Icons
- **Backend:** Google Apps Script (GAS)
- **Database:** Google Sheets
- **Libraries:** Summernote Lite (WYSIWYG 메일 템플릿 에디터), Kakao JS SDK (알림톡 연동)
- **Integration:** Google Calendar API, Gmail API

## 🌟 핵심 기능 (Key Features)

1. **예약 통합 리스트:**
   - 지점, 상태(대기/확정/취소), 예약금 여부에 대한 다중 복합 필터 및 정렬 기능.
   - 모바일 환경 최적화를 위한 터치 기반 **당겨서 새로고침(Pull-to-Refresh)** 및 인라인 예약 상태/예약금 상태 즉시 변경.
2. **실시간 동적 알림 (GNB Bell UI):**
   - 별도 DB 구축 없이 프론트엔드가 실시간 계산하여 알려주는 미결 상태 알림. 동일 예약 건에 대한 알림은 하나로 통합되고 다중 뱃지 형태로 노출됩니다.
    - **`[👥 중복 의심]`** (노란 뱃지, v2.1.0): 동일 이메일/고객명/연락처 기반 미래 예약 중복 감지 및 수동 묶음 그룹 알림.
    - **`[⚠️ 이메일 오류]`** (빨간 뱃지, v2.1.0): 이메일 정규식 형식 오류, 도메인 오타(gmial.com 등) 및 발송 실패(Mailer-Daemon 반송) 자동 감지.
    - **Optimistic UI 즉시 반영**: 주소 변경 재발송·스레드 초기화·예약 저장 요청 직후 해당 예약의 반송 상태와 관련 필터 카운트를 메모리에 반영하고, 실패 시 이전 상태를 복구합니다.
    - **`[임박]`** (빨간 뱃지, 1분마다 자동 갱신): 예약 대기 상태(`pending`)인 예약건 중 현재 시각 기준 **6시간 이내** 방문이 임박한 예약.
    - **`[예약대기]`** (노란 뱃지): 미래 방문건 중 확정 대기 중인 예약.
    - **`[예약금대기]`** (주황 뱃지): 미래 방문건 중 예약금 입금 대기 중인 예약.
    - **`[환불필요]`** (파란 뱃지): 방문 예정 시각이 지났으나 예약금이 완료(확정) 상태인 예약.
    - 알림 카드에서 예약 상세 모달로 이동하며, 중복 의심 예약은 목록의 그룹별 아코디언에서 함께 확인합니다.
3. **중복 예약 그룹 조회·관리·확인 메일 발송:**
   - 중복 의심 예약을 그룹별 아코디언으로 모아 데스크톱 테이블·모바일 카드에서 확인하고, 개별 예약 상세 모달로 연결합니다.
   - 개별 중복 제외, 단건 예약 취소, 전체 중복 제외, 관리자 수동 묶기 지원. 수동·자동 그룹 모두 동일한 제외 작업을 사용하며 별도의 수동 묶음 해제 기능은 제공하지 않습니다.
   - 중복 예약 리스트 그룹 접기/펼치기 아코디언 및 상단 일괄 토글 기능.
   - **스레드 기반 중복확인 메일 발송 (`ModalDuplicateMailSelect`)**: Gmail 스레드가 연동된 예약 건만 선택 가능하며(`메일발송 가능` 뱃지), 정형화된 영문 안내 메일 발송 및 `mail_sent_at` 자동 기록.
   - **메일 템플릿 & 레이아웃 최적화 (v2.1.1 ~ v2.1.3)**: 4바이트 이모지 인코딩 보장(`_encodeEmojisToEntities`), 좌측 정렬(`max-width: 680px`), 왕비집 서포트팀 표준 브랜드 테이블 푸터 본문 일체화(지메일 접힘 방지).
   - **발송 요청 즉시 반영과 실패 복구**: 요청 직후 발송 모달을 닫고 임시 발송시각·처리 중 로그를 반영합니다. 그룹 헤더에는 처리 중 스피너를 표시하고, 성공 응답의 실제 발송시각으로 확정하거나 실패 시 이전 값으로 복구합니다.
   - **개별·전체 중복 제외**: `excludeReservationFromGroup` 시트 삭제 및 고아 해제, RPC `earliestDate` Date 직렬화 버그 수정, 데스크톱/모바일 버튼 문구 완전 통일(`[확인메일 발송]`, `[전체 중복 제외]`, `[개별 중복 제외]`).
   - **신규 스레드 Gmail 라벨 상태 동기화 (v2.1.1)**: 주소 변경 재발송 및 신규 스레드 생성 시 예약 상태(확정/취소/대기/예약금)를 감지하여 지메일 라벨 정확히 동기화.
   - **다중 레이어 모달 ESC 계층 닫힘 제어**: Alert/Confirm 팝업 $\rightarrow$ 중복확인 모달 $\rightarrow$ 드롭다운 $\rightarrow$ 기본 상세 모달 순으로 닫히도록 완벽 격리.
   - 전용 DB 시트(`duplicate_group`) 및 `MigrationService`를 통한 스키마 자동 동기화, 10분 주기 정기 배치(`ReservationBatch.run10MinuteBatch`).
4. **지점 관리 및 슬롯 마스터/오버라이드 관리:**
   - 관리자 **지점 관리 → 지점 추가**에서 한글·영문 지점명, 기존 Google 캘린더 ID, 주소·구글맵 링크, 활성 상태를 등록합니다. 지점 ID는 서버에서 생성하며 영문 지점명과 캘린더 ID의 중복 등록을 막습니다. 캘린더 자체를 생성하지는 않습니다.
   - 추가 요청 직후 지점 목록·필터에 즉시 반영하고, 저장 성공 시 실제 ID로 교체하며 실패 시 임시 지점을 제거합니다. 기존 지점은 행을 클릭해 수정합니다. 설정 화면의 시트 구조 점검 버튼은 제거했습니다.
   - 특정 지점의 날짜별 슬롯을 일괄 제어(Batch API) 및 개별 재정의(ON/OFF) 기능.
   - 대량의 이벤트가 캘린더에 동기화되는 속도 향상을 위해 **Google Calendar Batch API** 및 백그라운드 지연 처리 큐 아키텍처 탑재.
5. **WYSIWYG 메일 템플릿 에디터 & 메일 연동:**
   - Summernote를 활용해 HTML 메일을 편집하고 예약 데이터 치환자(`[[customer_name]]` 등)를 적용하여 고객에게 안내 메일 발송.
   - 외부 위젯 연동 오류로 메일 스레드가 누락된 경우, 관리자가 즉시 **신규 메일 스레드를 강제 생성**하여 예약 확정 내역을 고객에게 전달하고 향후 원활한 템플릿 발송을 지원.
   - **Gmail 스레드 ID 자동 보정 (v2.2.1)**: 자유 입력 노트는 Gmail 검색어에서 제외하고, 검색 결과를 예약 요청 시각으로 좁힌 뒤 후보가 여러 개일 때만 메일 본문의 노트와 비교합니다. 검색 단계별 건수와 ID를 찾지 못한 예약을 로그에 남깁니다.
6. **구글 캘린더 및 Gmail 라벨 연동:**
   - 예약 확정/취소 시 캘린더 이벤트 자동 등록/삭제 및 Gmail 스레드에 관련 지점 및 예약 진행 단계 라벨 실시간 자동 동기화.
7. **조회 API 오류 재시도 (v2.2.0):**
   - Apps Script가 저장소 읽기 중 `INTERNAL` 오류를 반환하면 데이터 조회 API만 최대 2회 재시도합니다(총 3회 호출, 재시도 전 0.4초·0.8초 대기).
   - 예약 저장·상태 변경·메일 발송 등 데이터 변경 API는 중복 실행을 막기 위해 재시도하지 않습니다. 재시도가 모두 실패하면 기존 오류 처리로 넘어갑니다.
8. **Google 로그인과 권한 관리 (v2.2.6, 세션 보존 v2.2.19):**
   - Google OAuth 로그인 후 `/exec`로 돌아오는 인증 코드를 서버에서 교환합니다. 인증된 이메일이 활성화된 `user` 시트 계정과 일치해야 입장할 수 있습니다.
   - 로그인 화면의 버튼 문구는 `Google 계정으로 로그인`으로 고정하고, 로그인 URL 준비 전에는 버튼을 비활성화합니다. 사용자 등록 안내는 관리자 문의 문구로 표시합니다.
   - **iOS 홈 화면 앱의 계정 고정**: iOS 16.4 이상에서 Safari의 "홈 화면에 추가"는 추가 시점의 쿠키·저장소를 복사한 독립 웹앱을 만들며 이후 Safari와 분리됩니다. 앱 주소가 `script.google.com`이라 그 시점에 Safari에 로그인된 Google 계정 쿠키도 함께 복사되고, 홈 화면 앱 안에서는 그 계정으로만 로그인이 정상 동작합니다. 다른 Google 계정으로 로그인을 시도하면 계정 전환 흐름이 완료되지 않아 오류가 납니다. 사용할 Google 계정으로 Safari에서 먼저 로그인한 뒤 홈 화면에 추가하고, 계정을 바꾸려면 홈 화면 앱을 삭제하고 다시 추가합니다. Android Chrome의 홈 화면 바로가기는 Chrome 안에서 열려 쿠키를 공유하므로 이 제약이 없습니다.
   - 브라우저 `localStorage`에 무작위 세션 토큰을 저장합니다. 서버 호출 시에는 토큰을 `{token, ip}` 봉투로 보내며(v2.3.1), 서버는 봉투를 풀어 토큰만 검증하고 `ip`는 시스템 로그에만 사용합니다. 저장된 토큰이 유지되고 서버의 7일 만료 전이면 재접속 시 로그인 상태를 복원합니다. 앱 코드가 저장된 세션 토큰을 삭제하는 시점은 사용자가 명시적으로 로그아웃했을 때뿐입니다. 초기 세션 확인 실패·통신 오류·OAuth 응답 오류에는 기존 토큰을 보존하며, 사용자 정보 저장 후 세션 확인이 실패해도 자동 로그아웃하지 않습니다. 인증에 실패하면 보호된 화면과 API 접근은 차단합니다.
   - 명시적 로그아웃은 서버 세션을 폐기하고 앱 전용 로컬·세션 저장값과 화면 데이터를 지웁니다. 앱 전용 Cache Storage가 있으면 함께 정리합니다. 일반 브라우저 HTTP 캐시와 Google 계정 쿠키는 웹앱에서 지울 수 없습니다.
   - 각 API 요청마다 현재 계정 상태와 역할·지점 권한을 다시 확인합니다. 관리자만 사용자 정보를 변경할 수 있고, 매니저의 예약 조회와 지점 필터에는 허용된 지점만 표시됩니다. 허용 지점이 없으면 필터에 안내 문구가 나타납니다.

   - 웹앱 진입 시 사용자 목록과 `user_branch_permission` 시트의 활성 지점 권한을 함께 읽어, 사용자 수정 화면의 체크박스 선택 상태로 표시합니다.

## 🚀 배포 가이드 (Deployment via clasp)

예약 위젯의 별도 커스텀 코드는 `widget/elfsight/CustomJs.js`에 있습니다. Elfsight의 커스텀 JS 설정에 파일 내용을 적용하며, `clasp push` 대상(`src`)에는 포함되지 않습니다. 지점 목록의 **Hansik Wangbijib Central Branch** 이름 위에 `✨ Newly Opened` 배지를 표시합니다. 배지는 라일락·핑크·민트 그라데이션 배경과 보라색 글자의 둥근 형태이며, 노란 ✨ 이모지만 13px 크기와 짙은 골드 그림자를 적용해 선명하게 표시합니다. CSS 가상 요소로 표시하여 지점명 텍스트와 기존 예약 규칙의 이름 파싱을 보존하고 목록 재렌더링에도 다시 적용됩니다. **Wangbijib Myeongdong Central Branch**와 **Hansik Wangbijib Central Branch**는 지점명과 설명 사이에 `🧀 Get Free Grilled Cheese with Reservation` 안내 줄을 표시합니다. 안내 줄은 `STORE_CONFIGS`의 `promo` 값으로 지점별 설정하며, 제목 요소의 형제로 삽입해 지점명 파싱을 보존하고 목록 재렌더링 시 다시 적용합니다. Hansik Wangbijib Central Branch의 최대 인원은 46명입니다.

본 프로젝트는 Google Apps Script로 작성되었으며, `clasp` 도구를 사용하여 배포합니다.

### 1. clasp 설치 및 로그인
```bash
# 글로벌 clasp 설치
npm install -g @google/clasp

# Google 계정 권한 인증 (웹 브라우저를 통한 인증 완료 필요)
clasp login
```

### 2. Code Push (업로드)
프로젝트 루트 폴더에는 `.clasp.json` 설정 파일이 존재합니다.
```bash
# 로컬 수정 코드를 Google Apps Script 프로젝트의 Head에 업로드
clasp push

# 업로드 상태 유지하며 실시간 변경사항 감지 후 업로드
clasp push --watch
```

### Google 로그인 설정

이 브랜치의 로그인은 Google OAuth 웹 애플리케이션의 authorization code를 서버에서 교환합니다. `Config.GOOGLE_CLIENT_ID`와 **같은 OAuth 클라이언트**의 client secret을 Apps Script 프로젝트의 **Script Properties**에 `GOOGLE_OAUTH_CLIENT_SECRET` 이름으로 저장해야 합니다. 기존 secret이 노출되지 않았고 확인 가능하다면 재사용할 수 있습니다. 노출되었거나 확인할 수 없을 때만 새 secret을 발급하세요. secret을 소스 코드나 브라우저 코드에 넣지 마세요.

GCP의 Authorized redirect URIs에는 운영 배포의 정확한 `https://script.google.com/macros/s/.../exec` 주소를 등록합니다. 별도 테스트 배포를 쓰면 그 `/exec` 주소도 등록해야 합니다. 웹 앱은 **Execute as: Me**, **접근 권한: Anyone (`ANYONE_ANONYMOUS`)**로 배포하고, 앱의 보호된 API는 Google 로그인으로 발급한 세션을 검증합니다. 로그인 식별에 `UserProperties`나 브라우저의 이메일 값을 사용하지 않습니다.

로그인 후 브라우저 `localStorage`에는 무작위 세션 토큰을 저장합니다. 서버는 SHA-256으로 해시한 토큰 키와 만료 시각을 Script Properties에 저장하고, 6시간 CacheService는 조회 속도 향상에만 사용합니다. 브라우저에 토큰이 남아 있고 발급 후 7일이 지나지 않았으면 재접속하거나 서버 캐시가 비워져도 세션을 복원합니다. 만료된 토큰과 비활성 사용자는 서버에서 접근을 거부하며, 브라우저 토큰은 그대로 보존합니다. 새 Google 로그인이 성공하면 검증된 새 토큰으로 교체합니다.

앱 코드의 브라우저 저장값 정리는 명시적 로그아웃에서만 실행합니다. OAuth 검증용 일회성 `state`는 응답 처리 후 소비합니다. 초기 세션 확인이나 사용자 정보 저장 후 세션 확인이 실패해도 자동 로그아웃 또는 저장된 토큰 삭제를 실행하지 않습니다. 브라우저 자체의 사이트 데이터 삭제·저장소 정책까지 제어하는 기능은 아니므로 모바일 홈 화면 앱의 재접속도 실제 기기에서 확인해야 합니다. 사용자 비활성화 또는 권한 변경은 다음 요청부터 적용됩니다. 공용 기기에서는 사용 후 앱에서 로그아웃하세요.

배포 전에 `node --test tests/*.test.cjs`를 실행하세요. 60초 전체 동기화, 설정·로그의 응답 전 즉시 반영 및 실패 롤백, 생성 ID 교체, 늦은 동기화 응답 폐기도 테스트합니다. 인증 테스트는 초기 인증 실패 시 토큰 보존, 잘못된 OAuth 응답 처리, 사용자 정보 저장 후 인증 실패 시 자동 로그아웃 방지, 명시적 로그아웃 시 저장값 정리, `{token, ip}` 봉투 검증과 IP 조회 실패 시 빈 값 전송을 포함합니다. 시스템 로그 테스트는 `ip` 기록, 헤더 이름 매핑, 시트 부재 시 명시적 실패, 마이그레이션의 컬럼 추가를 포함합니다. 배포 후에는 `runSchemaMigration`을 실행해 `activity_log`에 `ip` 컬럼을 추가하세요. 배포 후 등록 계정 로그인, 브라우저와 모바일 홈 화면 앱 재접속 시 세션 복원, 로그아웃, 미등록 계정 접근 거부와 관리자 시스템 로그 표시를 `/exec`에서 확인합니다.
